# Capability 검증 계획 + 한계 항목 정밀 검토 — 2026-09-15

Part 1: 이미 구현된 탐지기 전체에 대한 검증 계획.
Part 2: 구조적 한계/미구현/원리적 불가 항목별 리서치 결과와 구현 방법.

## Part 1 — 탐지된 것 전체 검증 계획

### P1-0. 검증 매트릭스 구축 (1회성 기반 작업)

각 탐지기를 4개 열로 감사한다. `docs/DETECTOR-AUDIT-MATRIX.md` 생성:

| 열 | 질문 | 통과 기준 |
|---|---|---|
| 실행 | E2E로 실제 파일에서 동작하는가? | 스모크 테스트 1개 이상 |
| 측정 | 라벨 데이터에서 분별력이 측정됐는가? | AUROC/정밀도 수치 존재 |
| 보정 | 임계값이 코퍼스에서 정해졌는가? | 임계값 산출 근거 문서화 |
| 문서 | 한계가 결과/문서에 노출되는가? | limitations 필드 + docs |

현재 상태(감사 초안): 실행 ✅는 대부분, **측정은 텍스트만**, 보정은 거의 전무.

### P1-1. 모달리티별 라벨 벤치마크 코퍼스

검증의 선행 조건 — 신호가 실제로 구분하는지 측정할 데이터:

- **이미지**: Synthbuster(진행 중 3.4GB/11.8GB 다운로드), 자체 합성 케이스(복제/재압축/합성 삽입)
- **오디오**: 자체 생성 TTS샘플 + 실제 녹음; 화자 대조용 동일/다른 화자 쌍
- **비디오**: FaceForensics++ 스타일 조작 케이스 + 정상 영상
- **텍스트**: 기존 text-corpus(n=30) 확장 — 생성기별 라벨 필수

수용 기준: 각 탐지기별 최소 20 positive + 20 negative.

### P1-2. 자동화된 검증 스크립트

`experiments/audit_detectors.py` — 매트릭스의 각 탐지기를 코퍼스에 돌려 AUROC/EER/정밀도를 매트릭스에 자동 기입. `eval_text_detect.py` 패턴을 전 모달리티로 일반화.

### P1-3. 검증 실행 순서

1. 텍스트(기존 코퍼스로 즉시 가능) → 2. 이미지(Synthbuster 완료 후) → 3. 오디오(합성 케이스 생성) → 4. 비디오(샘플 확보 후)

### P1-4. 보정 작업

측정된 분별력으로 각 신호의 weight/임계값을 재산정 — 현재 weight는 전부 수동 추정치(측정 전 provisional 명시됨).

## Part 2 — 한계 항목별 정밀 검토 (리서치 완료)

### A. 구조적 한계 — 측정으로 확인됨

#### A-1. 기술/마크다운 문서의 AI 판별 실패 (PPL 61~131) ✅ 1단계 구현

**구현된 것**: `_technical_document_density` 게이트 — 코드펜스/표/헤더/HTML 태그/인라인코드 라인 비율 ≥40%면 목록·문장균일성 신호를 ×0.4로 감쇠하고 "측정된 실패 영역" 한계를 명시. 구조 자체가 고PPL이라는 진단은 PPL 신호 자체에는 적용 불가(외부 모델 점수라 사후감쇠 불가) — 문서화로 보완.
**남은 것**: 담론 수준 신호(PDTB 관계), 기술문서 전용 분류기는 코퍼스 확장 후.

**원인**: 표/코드/불릿/식별자는 LM에게 본질적으로 고PPL — 유창성 척도가 못 재는 영역.
**방법** (리서치):
- **DTransformer 계열 담론 신호** (arXiv 2412.12679): 문서 수준 구조 특징 — PDTB 담론 관계, 섹션 전이 패턴. paraWP에서 +4~15.5% 개선 입증 → 우리 마크다운 지문 신호의 정규화된 확장으로 구현 가능
- **산문-구조 이중 채널**: 이미 구현한 이중 뷰를 확장 — 구조 밀도가 높은 문서는 "기술문서 모드"로 PPL 대신 지문 신호만 쓰도록 게이팅
- **기술문서 전용 분류기**: devin/agent 산출물 라벨 코퍼스로 로지스틱 회귀 — 라벨이 이미 확보됨
**판정**: 구현 가능, 우선순위 높음 (A-1 게이팅 + 담론 신호).

**원인**: 표/코드/불릿/식별자는 LM에게 본질적으로 고PPL — 유창성 척도가 못 재는 영역.
**방법** (리서치):
- **DTransformer 계열 담론 신호** (arXiv 2412.12679): 문서 수준 구조 특징 — PDTB 담론 관계, 섹션 전이 패턴. paraWP에서 +4~15.5% 개선 입증 → 우리 마크다운 지문 신호의 정규화된 확장으로 구현 가능
- **산문-구조 이중 채널**: 이미 구현한 이중 뷰를 확장 — 구조 밀도가 높은 문서는 "기술문서 모드"로 PPL 대신 지문 신호만 쓰도록 게이팅

**판정**: 구현 가능, 우선순위 높음 (A-1 게이팅 + 담론 신호).

#### A-2. Humanized/구어체 AI 텍스트 회피 (PPL 107)

**원인**: 의도적 고PPL — 유창성과 반대 방향 조작.
**방법**:
- **Paraphrase-inversion** (arXiv 2410.21637): 패러프레이즈된 텍스트를 원문 근사로 복원 후 탐지 — 학습 데이터는 LM 패러프레이저로 자가 생성 가능. 소형 seq2seq로 구현 가능하지만 정확도는 파라프레이저 종속
- **PTD 스팬 탐지** (ACL 2024 Findings): 문장 단위 "패러프레이즈 됨" 점수 — 부분 humanization에 강함
- **적대적 robustness**: humanizing perturbation을 훈련/평가 데이터에 포함 (LREC 2024) — 우리 코퍼스에 humanized 샘플 추가로 최소한 측정은 가능
**판정**: 측정 코퍼스 추가(쉬움) → PTD 스타일 스팬 신호(중간) → inversion 모델(연구).

#### A-3. 백과사전체 사람 텍스트 오탐 (위키 51~76)

**원인**: 정제된 격식체는 AI와 유사한 저PPL/균일 구조.
**방법**:
- **도메인 조건 임계값**: 백과사전체 감지(객관적 지식서술, 인용 패턴) → 해당 도메인 전용 보정 임계값 적용
- **사람 기준 코퍼스 정규화**: 위키/백과사전 사람 코퍼스로 z-score 기준선 설정 — "이 텍스트가 사람 백과사전체보다 얼마나 더 AI스러운가"로 재표현
- **양측 검증 신호**: 오탐 경계에선 provenance/지문 신호 없으면 점수 캡 — 이미 부분 구현됨, 임계 조정 필요
**판정**: 코퍼스 확장 + 도메인 게이팅으로 완화 가능 (완전 해소는 불가 — 본질적 중첩 영역).

#### A-4. 짧은 텍스트 (<60어)

**방법**: 원리적으로 신호 부족 — 다음이 최선:
- 워터마크 검사 우선(키 알 때, 토큰 32개면 검정 가능)
- provenance 신호 비중 상향
- 점수 대신 "판정 불가" 명시 — 현재 limitation으로 이미 처리, 스코어 캡 추가 가능
**판정**: 완화만 가능. 신뢰도 표시를 길이 함수로 조정.

#### A-5. 생성기별 식별 (어느 모델인지)

**방법**:
- **생성기별 지문 프로파일**: 각 생성기의 대표 출력을 수집해 어휘/구조/토크나이저 통계 프로파일화 — LLMmap 스타일. 단, 실제 Codex/Claude/Gemini/Grok/Kimi 출력 샘플이 필요(현재 외부 결측)
- **거리-기반 귀속**: 각 생성기 프로파일의 stylometry 벡터와 거리 비교 — 분류가 아닌 "가장 가까운 프로파일" 보고
**판정**: 샘플 확보 시 구현 가능. 현재는 데이터 블로커.

#### A-6. 한국어 신경망 탐지기 오탐 (Fakespot/OpenAI ko 98점) ✅ 구현 완료

**구현**: 프로필에 `trained_languages: ["en"]` 필드 추가 → 앙상블 집계 시 hangul_ratio > 0.3이면 영어 전용 멤버 weight ×0.25 자동 감쇠 + 한계 명시. `analyze_external_model`(디렉터리 경로)와 `_analyze_profile_set` 양쪽에 적용. 언어 무관 멤버(Qwen PPL, Binoculars)는 영향 없음.
**남은 것**: 한국어 코퍼스 확장 시 언어별 재보정으로 개선 가능.

### B. 미구현 — 리서치로 방법 확인됨

#### B-1. SynthID

**리서치 결과**:
- **SynthID-Text는 오픈소스** (Apache-2.0, github.com/google-deepmind/synthid-text, HF transformers 4.46+) — weighted-mean 또는 Bayesian 검출기
- 단, **자기 키로 워터마킹한 텍스트만** 검출 가능 — Google 프로덕션 키는 비공개라 Gemini 출력은 Google SynthID Detector 포털로만 확인 가능
- 이미지/오디오/비디오 SynthID: 검출기 전부 비공개, 포털만
**구현 방법**: KGW와 같은 방식 — `synthid-text` 패키지로 알려진 키의 SynthID 검출을 추가(선택 의존성). Gemini 등 공개 출력은 "포털로 확인" 안내만. **판정**: 부분 구현 가능.

#### B-2. 조명/그림자 물리 일관성

**리서치 결과**:
- **Farid 방식** (WIFS 2010, TOG 2013): 단일 이미지에서 저차원 조명 모델 추정 → occluding boundary의 2D 법선으로 광원 방향 복원 → 여러 객체의 제약을 선형계획으로 물리 일관성 검정. 순수 수치 구현 가능(복잡하지만 외부 자산 불필요)
- **Phantom Lens 스타일**: 얼굴 영역 vs 배경의 조명 불연속, 반사광 대칭성 — MediaPipe 랜드마크 + 단순 특징으로 구현 수준 낮음
**판정**: Farid 경량판(얼굴 영역 조명 방향 vs 배경 추정 방향 비교) 구현 가능 — 얼굴 조작에 특화된 물리 신호.
**✅ 구현 완료** (`face.py::_lighting_consistency`): 얼굴 좌우/상하 음영 비대칭(조명 방위 프록시) vs 주변 링의 최소제곱 조명 램프 기울기 비교, ≥60° 불일치 시 신호 발동. 균등 조명·무특징 배경이면 자동 억제. 합성 검증: 180° 불일치 정확 플래그, 일치 시 무발동. `--deep-signals` 얼굴 경로에 통합.

#### B-3. 학습형 립싱크 (SyncNet)

**리서치 결과**: `joonson/syncnet_python` — 사전학습 가중치 공개 다운로드(`download_model.sh`), PyTorch, PyPI 패키지 `syncnet-python` 0.2.2 존재.
**구현 방법**: model_adapter 프로필로 추가 — syncnet_v2.model 가중치를 `models/` 자산으로, runtime이 입 영역 프레임+MFCC를 먹여 오프셋/신뢰도 출력. 라이선스는 연구용 CC — 재배포 시 주의.
**판정**: 구현 가능 — 외부 가중치 다운로드만 필요. AASIST 패턴 그대로.

#### B-4. 회전/스케일 강건 copy-move ✅ 구현 완료

**구현**: `frequency.py::copy_move_keypoint_score` — SIFT(→ORB 폴백) 키포인트 매칭 + **쌍별 유사변환 투표** (소표본 RANSAC은 퇴화 변환을 선택해 실패 — 실측으로 확인) + **광도 검증** (워프된 소스 패치와 목적지 픽셀 비교, MAD < 0.35·영역표준편차). 미러 매칭(A→B/B→A)이 섞인 가짜 가설은 광도 검증이 걸러냄. Lowe ratio test는 복제 영역에서 구조적으로 실패 — 적응형 거리 임계(0.5·중앙값)로 대체.
**측정**: 이동 복제 0.15 / 스케일 복제 0.05 / 회전+노이즈 0.125 검출, 깨끗한 텍스처·노이즈 0. 실사진에서는 대형 중복 패널을 정확히 검출(스크린샷 템플릿 반복은 진짜 복제라 플래그 — 리뷰 필요 영역). 저텍스처 이미지의 40°+ 회전은 키포인트 부족으로 미달 가능 — 정직한 한계.
**배선**: `frequency_forensics` 엑스퍼트에 블록 방식과 병행 (≥0.12→점수 55, ≥0.05→약신호). cv2 없으면 graceful degrade.

#### B-5. 진짜 화자 인식 (임베딩) ✅ 구현 완료

**구현**: `compare_speakers`가 speechbrain 설치 시 ECAPA-TDNN(spkrec-ecapa-voxceleb, ~90MB HF 다운로드)으로 검증, 없으면 MFCC 폴백. 발견된 함정: Windows 심볼링크 권한(LocalStrategy.COPY로 우회), torchaudio 2.11의 torchcodec 의존(soundfile로 대체), m4a/aac는 ffmpeg→wav 변환, verify_files의 Windows 경로 버그(verify_batch+텐서로 우회).
**실측**: 자기 녹음 m4a → 100 same, 통화녹음 vs 음성메모 → 20 different (ECAPA 경로). MFCC는 동일 쌍에 97 same 오탐이던 것이 개선.
**판정**: 구현 가능 — pip 패키지 + HF 다운로드.

#### B-6. 저자 귀속 (누가 썼는지)

**방법**: 스타일 프로파일 라이브러리 — 알려진 작성자 샘플들의 stylometry 벡터 DB, 최근접 귀속 + 거리 신뢰도. 샘플 확보가 전제.
**판정**: 샘플 확보 시 구현 가능.

#### B-7. HWP 텍스트 추출

**리서치 결과**: `syhwp` (MIT, 순수파이썬, olefile만 의존) 또는 `hwpkit` — `.hwp`/`hwpx` 둘 다 지원, Python 3.9–3.13. pyhwp는 Python2 기반이라 비추.
**구현 방법**: `documents.py`에 syhwp 경로 추가 — `import syhwp` 성공 시 extract, 실패 시 현재 graceful 유지.
**판정**: 즉시 구현 가능 — 가장 쉬운 미구현 항목.

#### B-8. 영상/오디오 C2PA ✅ 확인 완료 (이미 지원됨)

**확인**: `analyze_metadata_forensic`/`validate_c2pa_manifest`는 처음부터 포맷 무관 — `c2pa.Reader`가 mp4/mov/wav를 네이티브 파싱함을 실측 (`present: False` 정상 반환, 에러 아님). webapp/api_server/cli의 모든 업로드 경로에 이미 배선. 실제 갭은 c2pa-python 미설치 환경뿐이었음 — `provenance` extra 설치로 해결.
**테스트**: mp4 컨테이너 파싱 회귀 테스트 추가.

#### B-9. 점수 확률 보정

**방법**: 라벨 코퍼스에서 각 탐지기 점수를 isotonic/Platt 회귀로 확률 매핑 — "score 67"이 "AI일 확률 ~X%"로 번역되도록. P1 벤치마크 데이터가 선행.
**판정**: P1 데이터 확보 후 구현 가능.

### C. 원리적 불가 — 완화만 가능

| 항목 | 완화 방법 |
|---|---|
| 점수=확정 판정 | B-9 보정으로 "신뢰도%" 제공 — 판정이 아닌 측정 신뢰도 |
| 키 모르는 워터마크 | KGW/SynthID 둘 다 키 필요 — 공개 키 모으는 레지스트리 유지만 가능 |
| 강력 후처리(재압축/변환) | robustness eval로 각 신호의 생존 한계 측정 → limitation에 정량 명시 |
| 신규 생성기 | 지속 eval 파이프라인 — 새 샘플 들어오면 코퍼스에 추가하는 워크플로 |
