## 판정: 머지 가능 (Low 3건은 후속 작업으로 처리 가능)

**결론:** Low보다 심각한 문제는 찾지 못했습니다.

- **K-1~K-7:** 모두 직접 재현해 닫힌 것을 확인했습니다.
- **409 상태 기계:** 아래 경우 모두에서 잘못된 표시, 숨겨진 거부, 엉뚱한 검사의 다운로드가 없었습니다.
  - 늦게 도착한 409와 늦게 도착한 성공
  - 다른 폴더 검사, 다시 검사, 아카이브, NFD 이름, 중복 원본
- **서명 산출물(두 서버):** 서명 무결성, 미리보기 = PDF, 호증 순서, 쪽별 문구, 법조 미기재가 모두 유지됩니다. rev4 이후 Python 서버 코드는 바뀌지 않았습니다(diff는 gui.js/html/css, 시험, 문서뿐).
- **게이트:** 전체 게이트 rc=0, gui_smoke PASS입니다. 새 시험은 rev4에서 실패합니다.

**남은 3건(L-1~L-3, 모두 Low):** K-2와 K-5 수정의 가장자리에 있습니다. 화면이 실제와 맞지 않거나 이유가 보이지 않는 곳에 뜨는 문제입니다. 서명되는 산출물은 정직합니다. 서버가 링크된 폴더 뒤의 행을 HTML/PDF/증거설명서 안에 "서명 제외 … 재분석하지 못했습니다"로 스스로 밝힙니다. 따라서 잘못된 문서가 서명되는 경로는 없습니다.

## 새로 찾은 문제

Medium 이상은 없습니다. 아래는 모두 Low/Info입니다.

### L-1 (Low) — "지우기" 뒤에도 409 알림과 확인 목록의 "검사 뒤 바뀐 파일"이 남음
- **재현:**
  1. fx를 검사한 뒤 a1111.png와 plain.png를 바꾸고 서명된 JSON을 누릅니다(409).
  2. 대장 메뉴에서 "지우기"를 누르고 확인합니다.
  3. 감정서 화면으로 갑니다.
- **결과:**
  - 미리보기는 "검사 결과가 없습니다"입니다.
  - 그런데 #export-alert는 그대로 "검사 뒤 바뀐 파일 2개 — 내보내지 않았습니다 … a1111.png — 조작·생성 근거 있음 → 판단 불가 …"를 보입니다.
  - 확인 목록에도 "필수 검사 결과가 없습니다"와 "필수 검사 뒤 바뀐 파일 2개(다시 검사 필요) — 서버가 내보내기를 거부했습니다"가 함께 있습니다.
  - 상단 오류 상자만 지워졌습니다.
- **원인:** `$('exp-clear')` 핸들러가 `resultsGeneration += 1; clearExportRefusals();`만 하고 `changedPaths`·`changedInfo`를 비우지 않습니다. `renderExportAlert()`도 부르지 않습니다(gui.js 2245–2247). `processResults()`는 이 일을 모두 합니다.
- **영향:** 결과가 없는 화면이 "검사 뒤 바뀐 파일"이 있다고 말합니다. 다음 검사나 업로드에서 지워지고, 결과가 없으니 내보낼 수도 없습니다. 거짓 경고이지만 해는 작습니다. 이 회귀는 K-2 수정이 새로 만든 것입니다(rev4에는 알림·목록 항목이 없었음).
- **수정:** 지우기에서 `changedPaths = new Set(); changedInfo = new Map(); renderExportAlert();`를 하거나, 결과를 바꾸는 공통 함수를 하나 둡니다. smoke나 node 시험에 "409 → 지우기 → #export-alert hidden"을 추가합니다.

### L-2 (Low, K-2 잔여) — 409가 아닌 거부와 K-5 "서명 제외" 주의가 여전히 화면 위쪽 오류 영역에만 뜨고, K-5 주의는 다음 성공 내보내기에 지워짐
- **재현(1366×768, 버튼을 화면 가운데로 스크롤):**
  1. fx를 재귀로 검사합니다. 기본 서증에 sub/deep.png(조작·생성 근거)가 포함됩니다.
  2. `fx/sub`를 다른 폴더로 가는 심볼릭 링크로 바꿉니다.
  3. **증거설명서(PDF)를 누름:** 서버가 400 `exhibit_not_rederived`를 돌려줍니다.
     - 이유 상자 "다시 분석할 수 없는 서증: sub/deep.png(경로 중간의 폴더가 심볼릭 링크라 …)"는 top=-671px로 화면 밖에 있습니다.
     - 버튼 옆에는 "증거설명서(PDF) — 만들지 못했습니다."만 보입니다.
     - #export-alert는 hidden이고 "다시 검사" 버튼도 없습니다. 확인 목록도 바뀌지 않습니다.
  4. **서명된 JSON을 누름:** 다운로드는 됩니다.
     - "주의 … 서명 제외로 옮겨졌습니다 — sub/deep.png …" 상자는 top=-694px로 화면 밖에 있습니다.
     - 버튼 옆은 "서명된 JSON — 내려받았습니다."입니다.
  5. **이어서 HTML 보고서를 누름(200):** 성공 경로의 `clearExportRefusals()`가 위의 "주의" 상자를 지웁니다.
     - 이 HTML도 sub/deep.png를 서명 제외로 옮긴 같은 상황입니다.
     - 산출물 안에는 적혀 있지만 GUI에는 아무 표시도 남지 않습니다.
- **원인:**
  - K-2는 409(`action === '바뀜'`)만 #export-alert로 보냅니다. 나머지 거부는 `toast(…, true)` → `showError`로 위쪽 영역에 갑니다.
  - K-5 주의는 `showError(…, startGen)`로 `data-export-gen`을 달아 만듭니다. 그런데 이 표지가 "거부"와 "주의"를 구분하지 않습니다. 그래서 다음 성공이 둘을 함께 지웁니다.
  - HTML/PDF 성공에는 제외 행 확인이 없습니다(JSON만 확인).
- **영향:** "왜 거부됐는지 분명히 말한다"가 409 밖에서는 아직 지켜지지 않습니다. K-2에서 고친 결함과 같은 종류이고, K-5 상황에서 사용자가 가장 먼저 겪는 경로입니다. 산출물 자체는 정직합니다.
- **수정:**
  - 내보내기 실패 전체(적어도 `exhibit_not_rederived`·`exhibit_unknown`)를 #export-alert 또는 버튼 옆 `role=alert` 상자로 보내고, "다시 검사"를 붙입니다.
  - "서명 제외" 주의는 거부 표지와 분리합니다. 같은 결과 세대 동안 유지하고, 버튼 옆에도 표시합니다.
  - 가능하면 HTML 성공 응답에서도 제외 행을 알립니다. 서버가 헤더(예: 제외 행 수)를 주면 됩니다.

### L-3 (Low/Info) — 동시에 진행한 두 내보내기에서 화면이 서로 어긋날 수 있음(코드 판독)
- **상황:** 같은 결과로 HTML과 서명된 JSON을 거의 동시에 누르고, 그 사이 파일이 바뀌는 경우입니다. JSON은 409, HTML은 200(바뀌기 전에 재분석됨)일 수 있습니다.
- **코드 동작:** HTML 성공이 나중에 도착하면 `clearExportRefusals()`가 409 상세 상자를 지웁니다. `changedPaths`는 그대로이므로 #export-alert "검사 뒤 바뀐 파일 n개 — 내보내지 않았습니다"는 남습니다. 그런데 버튼 옆 안내는 "HTML 보고서 — 내려받았습니다."가 됩니다.
- **결과:** 내려받은 HTML은 그 시점에는 정확합니다. 다만 화면은 "내보내지 않았다"와 "내려받았다"를 함께 말합니다.
- **재현:** 브라우저에서 타이밍을 맞추지 못해 재현하지 못했고, 코드 경로만 확인했습니다.
- **수정:** 성공 경로에서도 `changedPaths.size`가 있으면 안내를 "…내려받았습니다(이 파일은 바뀌기 전에 만들어짐). 이후 바뀐 파일이 있어 다른 서명 형식은 다시 검사 후"로 씁니다. 또는 409를 받은 뒤 도착하는 같은 세대의 성공 응답은 다운로드하되 경고를 지우지 않습니다.

### Info
- **K-4 잔여:** sha256과 결론이 같고 status만 다른 409 행(예: 검사 때와 다른 환경에서 검사 하나가 실패로 바뀜)은 여전히 "판단 불가 → 판단 불가"로 나옵니다. 서버 서명 `(sha256, status, verdict_code)` 중 status만 다른 경우입니다. 드물어서 Info로 둡니다.
- **무시 안내의 수명:** "이전 검사에 대한 응답이라 무시했습니다"는 일반 토스트라 4초 뒤 사라집니다. export-note의 같은 문구도 화면을 다시 그리면 덮입니다. 늦게 도착한 성공 다운로드가 버려졌다는 사실이 남지 않습니다.
- **두 번 낭독:** 409는 #export-alert(role=alert)와 #error-region(aria-live=assertive) 양쪽에서 낭독됩니다.

## 이상 없음으로 확인한 공격
- **상태 기계:**
  - 검사 중 내보내기 버튼 비활성
  - 409 뒤 반복 클릭: aria-disabled, 이유 안내, 요청 없음
  - 409 → 다시 검사 → 재검사 → 성공 시 상자·알림·목록 해제
  - 다른 폴더 검사로 늦은 409 무시, 지우기로 늦은 응답 무시
  - 재검사 실패 시 표시 유지(정직)
  - 아카이브 구성원과 컨테이너 동시 표시, NFD 이름 표시
- **XSS:** `<img src=x onerror=alert(1)>.png`를 바꿔 409를 냈습니다. #export-alert, 오류 상자, 대장 표시, 상세 창, 미리보기 "(검사 뒤 바뀜)" 행에서 삽입 요소 0개, alert 호출 0회였습니다. 사건 칸에 `<script>`·`<img onerror>`를 넣어도 미리보기와 확인 목록에 글자 그대로 나옵니다.
- **서명 산출물(8831 stdlib, 8834 FastAPI):**
  - 변경 전 5형식 모두 200입니다.
  - 미리보기 대 증거설명서 PDF 텍스트(공백 제거 포함 비교): 원고/피고 × dedupe 유/무 × 두 서버, 8조합 모두 누락은 `file_path` 원시 필드 2개(인쇄 대상 아님)뿐입니다.
  - 호증 순서는 `exhibit_paths` 순서(sub/deep.png, zip 구성원, a1111.png, a\u2800b.png, XSS 이름)를 따르고 PDF 위치도 증가 순입니다.
  - 갑/을 수는 원고 5/0, 피고 0/5입니다.
  - 법조는 "관련 법조: (검토자 기재 …)"만 있고 형법 조문 등은 없습니다.
  - evidence-json은 두 서버 모두 `verify-report`에서 "검증됨"입니다.
