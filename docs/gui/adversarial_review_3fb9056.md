# GUI 재설계 적대적 리뷰 3차 (gui-redesign 3fb9056)

## 판정: 수정 후 머지 (J-1을 고치기 전에는 머지하지 않을 것)

2차 지적 H-1~H-10 중 서버 쪽 다섯 건(H-1, H-4, H-7, H-9, H-10)은 실제로 닫혔습니다. 직접 확인한 내용은 다음과 같습니다.
- `exhibit_paths`가 보낸 순서대로 호증 번호를 정합니다.
- 비어 있거나, 중복이거나, 모르는 경로이거나, 올린 파일이거나, NFC로 바꾼 경로는 stdlib 서버와 FastAPI 서버 모두 400입니다.
- 부록 행의 판단 불가 종류와 한 줄 요약은 서명에 포함되어, 바꾸거나 빼면 `tampered`로 검출됩니다.
- 원고 측 기본 출력은 base와 바이트 단위로 같습니다. CLI MD·JSON이 같고, CLI·웹 증거설명서 PDF 텍스트도 같습니다.
- 전체 게이트는 rc=0이고 gui_smoke도 PASS입니다.

그런데 이번 라운드의 핵심인 "미리 본 것이 곧 서명되어 나가는 것"이 여전히 성립하지 않습니다. 미리보기(`evidence-preview`)는 화면에 있는 행으로 만들고, 내보내기는 서버가 파일을 다시 분석해서 만듭니다. 서버는 두 결과가 다를 때 이를 알아채지 못합니다. 검사 뒤 파일이 바뀌었거나, 압축 파일의 구성원이 바뀌었거나, 중복 제거 옵션을 켰다면 서명된 증거설명서의 같은 호증 번호에 다른 결론이 찍힙니다. 서버는 200을 돌려주고, GUI는 "내려받았습니다"라고만 표시합니다(J-1, J-2). 게시된 행에 이미 `sha256`이 들어 있으므로 서버가 비교만 하면 막을 수 있습니다. 수정은 작습니다.

그 밖에 다음 문제가 있습니다.
- 미리보기 표의 입증취지·작성자 칸에 `\n`이 글자 그대로 찍힙니다(J-3).
- 사건 정보 칸 하나만 고쳐도 폴더 확인이 조용히 풀립니다(J-4). H-8 수정을 우회하는 경로입니다.
- 취소된 검사가 다른 화면에서 끝나면 초점을 빼앗습니다(J-5). H-5의 잔여입니다.

J-1은 법정 제출 문서가 화면에서 확인한 내용과 달라질 수 있는 문제여서 머지를 막는 사유로 봅니다. J-2부터 J-4까지는 같은 PR에서 함께 고치기를 권합니다.

## 새로 찾은 문제

### J-1 (High) — 검사 뒤 파일이 바뀌면, 미리 본 증거설명서와 다른 내용이 조용히 서명됨
- **재현 1 (파일 교체):** hostile 폴더를 검사합니다. GUI에서 의뢰 측을 피고로 두고 기본 선택을 유지하면 미리보기는 `을 제1호증 dalle.jpg [자동 분석 결론: 조작·생성 근거 있음 …]`입니다. 디스크의 dalle.jpg를 plain.jpg 내용으로 바꾼 뒤, GUI가 만든 `exportPayload('evidence')`를 `format=evidence-json`으로 보냈습니다.
  - 결과는 200입니다. 서명본은 `을 제1호증 dalle.jpg 판단 불가 (sha256 3fff53dc…)`입니다.
  - 사건 대장은 여전히 `manipulation_evidence`를 표시합니다.
  - 반대로 dalle 내용이 들어간 plain.jpg는 부록에 `조작·생성 근거 있음`으로 실립니다. 검사관이 조작 근거가 있는 파일을 일부러 서증에서 뺀 것처럼 읽힙니다.
  - `format=evidence` PDF도 같습니다. 본문 `을 제1호증 … dalle.jpg`, 부록 `plain.jpg — 조작·생성 근거 있음 — SHA-256: ce10…`입니다.
- **재현 2 (압축 구성원 교체):** evid.zip 안의 `inner/sd.png`를 평범한 PNG로 바꿨습니다. 미리보기는 그대로 제2·3호증 "조작·생성 근거 있음"인데, 서명본은 `을 제2호증 evid.zip 판단 불가 / 을 제3호증 evid.zip::inner/sd.png 판단 불가`이고 응답은 200입니다.
- **재현 3 (서증이 아닌 파일 삭제):** mj.png를 지웠습니다. 미리보기 부록에는 `mj.png — 판단 불가(단서 1건) — SHA-256 …`이 있습니다. 서명본에서는 부록에서 빠지고 `excluded_items`(서명 제외)로 옮겨집니다. 서증 파일을 지운 경우에만 400입니다(`unknown_exhibit_paths: ["dalle.jpg"]`).
- **원인:** `_report_payload`는 `evidence-preview`일 때만 다시 분석하지 않습니다(webapp_api.py `req_format == "evidence-preview"` 분기). 내보내기는 `_rederive_report_items`의 결과로 서명하는데, 게시된 행의 `sha256`·status·verdict와 다시 분석한 행을 비교하는 코드가 없습니다. 게시된 행에는 `sha256`이 들어 있습니다(`res['items'][0]['sha256']`).
- **영향:** 검사관이 화면에서 확인하고 인용한 "을 제1호증 = 조작·생성 근거 있음"이, 서명된 제출 문서에서는 "판단 불가"가 됩니다. 서명이 유효하므로(`verify-report` verified) 사후에 알아챌 방법도 없습니다. 미리보기 아래의 "실제 문서는 서버가 파일을 다시 분석해 만들고…" 안내만으로는 무엇이 달라졌는지 알 수 없습니다. 사건 대장 대 서명 JSON·HTML·감정 PDF의 차이는 base에도 있던 0단계 결함입니다. 다만 이번 재설계가 "서버의 증거설명서 서식 그대로 미리 봅니다"라고 약속하면서 이 결함이 정면으로 드러났습니다.
- **수정:** 서버가 다시 분석한 행의 `sha256`(구성원은 구성원 해시)·status·verdict_code를 게시된 행과 비교합니다. 하나라도 다르면 모든 서명 형식(`evidence`, `evidence-json`, `pdf`, `html`, `json`)에서 409를 돌려주고 `changed_rows: [{path, posted_sha256, server_sha256, posted_verdict, server_verdict}]`를 담습니다. GUI는 "검사 뒤 바뀐 파일 n개 — 다시 검사하십시오"를 띄우고 해당 행을 표시합니다. 테스트도 붙입니다. 검사 → 파일 교체 → 내보내기는 409, 구성원 교체도 409, 서증이 아닌 행을 지워도 409(또는 미리보기에 서명 제외로 표시)여야 합니다.

### J-2 (Med) — "같은 내용의 파일은 한 번만 검사"를 켜면 미리보기와 서명본의 결론이 다름
- **재현:** a_dalle.jpg와 내용이 같은 b_dalle_copy.jpg를 두고 `dedupe=true`로 검사했습니다. b_dalle_copy는 status `duplicate`, 대역 "분석 못 함"이라 기본 선택에서 빠집니다.
  - 미리보기 부록: `b_dalle_copy.jpg — 중복 — SHA-256: ce10…`
  - 서명본(`evidence-json`) 부록: `{'file_path': 'b_dalle_copy.jpg', 'verdict_label': '조작·생성 근거 있음', …}`
  - hostile 폴더에서 "분석 못 함"까지 서증으로 고르면, 미리보기의 `갑 제21~23호증 copyA/copyB/mj_copy2 — 중복`이 서명본에서는 `판단 불가`가 됩니다.
- **원인:** 다시 분석할 때는 파일을 하나씩 분석하므로 중복 상태가 재현되지 않습니다. 미리보기는 게시된 상태를 씁니다.
- **영향:** 조작 근거가 있는 사본이 확인 목록의 경고 없이 서명된 부록에 "조작·생성 근거 있음"으로 들어갑니다. 서증으로 넣지 않은 이유가 문서상 설명되지 않습니다. 서명 JSON·HTML(중복 → analyzed)의 차이는 base에도 있습니다.
- **수정:** 서버가 다시 분석할 때 `duplicate_of`를 보존해 중복 상태를 재현하거나, J-1의 비교에 status를 넣어 409를 냅니다. GUI는 중복 행의 대역을 원본 행의 결론으로 보이게 하고, 확인 목록에 "부록으로 가는 중복 행 중 조작·생성 근거 있음 n개"를 경고합니다.

### J-3 (Med) — 미리보기 표에 `\n`이 글자 그대로 찍힘 (미리보기 ≠ PDF)
- **재현:** 감정서 화면의 미리보기 첫 행 입증취지는 `…직접 증거가 아님]\n결정적 근거(생성 도구 메타데이터)에 의해 …\n• 결정적 근거: …\n• 원본 SHA-256: …`입니다. `td.a4-purpose`의 innerHTML에 백슬래시와 n 두 글자가 들어 있고, `white-space: pre-line`은 아무 효과가 없습니다. 법무법인을 입력하면 작성자 칸도 `법무법인 테스트\n2026. 10. 12.`가 됩니다. PDF는 이 자리에서 줄을 바꿉니다. 375px 어두운 모드 화면에서도 같았습니다.
- **원인:** `a4Html`이 `shown(e.purpose_of_proof)`를 씁니다. `shown = escapeHtml(displayName(...))`이고, `displayName`이 제어 문자(개행)를 `\n` 표기로 바꿉니다(R10-1의 파일 이름 방어). 서식 문장에 이름용 방어를 적용한 것입니다.
- **영향:** 미리보기가 산출물과 다르게 보이고 읽기 어렵습니다. smoke와 단위 시험은 상자·사건 칸·서명란 줄만 PDF와 비교하고 표 칸은 비교하지 않아 이 문제를 놓쳤습니다.
- **수정:** 서식 텍스트는 `\n`으로 나눈 뒤 줄마다 `shown()`하고 `<br>`로 잇습니다. 파일 이름 부분은 이미 서버가 `row_label`로 이스케이프했습니다. smoke에 표 칸 비교(공백을 없앤 뒤 PDF 포함 여부)를 붙입니다.

### J-4 (Med) — 사건 칸 하나만 고쳐도 폴더 확인(H-8)이 조용히 풀림
- **재현:** hostile에서 사건번호 2026가합1·사건명 손해배상을 입력했습니다. big 폴더를 검사하자 확인 목록에 필수 항목 "사건 정보는 다른 검사(hostile)에서 입력되었습니다"가 떴고, `caseUnconfirmed() === true`였습니다. 이 상태에서 법무법인 칸에 입력하니 `caseUnconfirmed() === false`, `caseFolder = root:…/big`이 되었습니다. 필수 항목은 사라지고, 사건번호 2026가합1은 그대로 big 폴더 증거설명서에 실립니다. 그 뒤 hostile을 다시 검사하자 거꾸로 "다른 검사(big)에서 입력되었습니다"라고 표시했습니다. 의뢰 측 라디오를 바꿔도 같습니다(`onCaseChange → saveCase()`).
- **추가:** 올린 파일은 범위가 모두 `'upload'` 하나라서, 서로 다른 사건의 업로드 사이에서는 확인을 묻지 않습니다.
- **수정:** `saveCase()`가 `caseFolder`를 바꾸지 않게 합니다. 묶음은 "이 폴더의 사건이 맞음" 버튼, 또는 사건번호·사건명을 바꿀 때만 바꿉니다. 업로드 범위에는 배치 식별자(첫 파일 이름과 시각 등)를 넣습니다. smoke에 "다른 칸 수정 뒤에도 필수 항목 유지" 검사를 붙입니다.

### J-5 (Low-Med) — 다른 화면에 있는 동안 취소된 검사가 끝나면 초점을 빼앗음 (H-5 잔여)
- **재현:** 500장 폴더를 검사하다가 "중단"을 누르고 곧바로 감정서 화면으로 가서 `case-plaintiff`에 초점을 두었습니다. 부분 결과가 도착하자 `document.activeElement`가 `rep-h`로 바뀌었고 띠는 숨겨졌습니다(오류 영역에는 "검사 취소 — 부분 결과 397개 행…").
- **원인:** 취소 경로는 `focusSafely($('view-results-btn'))`을 씁니다. 버튼이 보이지 않으면 `viewHeading(currentView)`로 초점을 옮깁니다(gui.js 1181, 1256). `showResultsWhenDone()`을 거치지 않습니다.
- **수정:** `currentView !== 'scan'`이면 초점을 옮기지 않고 띠에 "검사가 취소되었습니다 — 부분 결과 보기"를 띄웁니다.

### J-6 (Low) — 의뢰 측을 고르기 전에 미리보기와 감정 PDF가 원고(갑) 서식을 씀
- 확인 목록은 "의뢰 측을 고르지 않았습니다 — 기본값은 없습니다"라고 하는데, 미리보기는 "원고(고소인)의 소송대리인은 … 갑 제1호증"으로 그려집니다(서버 기본값이 plaintiff). 감정 보고서 PDF도 의뢰 측 없이 내보낼 수 있고 `exhibit_no`가 "갑 제 호증"으로 나갑니다(`exportBlockReason('pdf')`는 의뢰 측을 요구하지 않습니다).
- **수정:** 의뢰 측이 없으면 미리보기 머리말과 호증 칸에 "(의뢰 측 미선택)"을 표시합니다. 감정 PDF는 의뢰 측을 요구하거나 호증 칸을 비웁니다.

### J-7 (Low) — 400 응답의 `unknown_exhibit_paths`를 GUI가 보여 주지 않고, 원인 설명도 틀림
- `apiError()`는 `error`만 읽습니다. 그래서 토스트에 "exhibit_paths 중 1개는 이 보고서의 서명된 행이 아닙니다(unknown_exhibit_paths 참조)"만 나오고, 참조하라는 목록은 어디에도 없습니다. 검사 뒤 서증 파일이 지워진 경우(J-1 재현 3) 실제 원인은 "서버가 다시 분석할 수 없음"인데, 메시지는 "서명된 행이 아님"이라고 합니다.
- **수정:** 토스트나 오류 영역에 경로 목록(최대 n개)을 표시하고, 다시 분석에서 빠진 경로는 그 이유(`REPORT_ROW_NOT_DERIVED`/파일 없음)로 따로 말합니다.

### J-8 (Low) — 올린 파일만 있을 때 확인 목록이 따를 수 없는 안내를 함
- 텍스트 파일 2개를 올리고 판단 불가·분석 못 함 칸을 모두 골라도 `selectedEntries().length === 0`입니다(H-1 수정으로 올린 파일은 서증이 될 수 없음). 그런데 확인 목록은 "근거 있는 파일이 없으면 판단 불가 칸을 고를 수 있습니다"라고 안내하고, 칸 옆 숫자는 해당 개수를 그대로 보여 줍니다. 폴더와 업로드가 섞인 경우에는 "나머지 m개는 증거설명서 부록에" 문구가 업로드 행까지 셉니다. 실제로 업로드 행은 서명 제외 칸으로 갑니다.
- **수정:** 올린 파일은 증거설명서 서증이 될 수 없다는 점을 확인 목록에 명시하고, 부록 개수에서 업로드 행을 뺍니다.

### J-9 (Low) — 판단 불가 분할의 숫자와 순서가 화면마다 다름

- **수정:** 헤드라인에 "(검사 실패가 겹친 단서 행 1개 포함)" 같은 겹침 표시를 넣고, 두 순서를 하나로 맞춥니다.
